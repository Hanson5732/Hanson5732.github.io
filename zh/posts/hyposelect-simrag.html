HypoSelectSimRAG: 基于多路径自一致性查询转换提高 RAG 答案精度

作者：龙坤良、黄瀚祺、赵翔宇 等

1. 传统 RAG 与 HyDE 面临的瓶颈

传统的检索增强生成（Standard RAG）高度依赖直接从用户原始查询（raw query）计算得到的稠密向量（dense vector）进行相似度检索。然而在实际场景中，用户往往使用口语化、信息不完整或带有歧义的措辞表达复杂的检索需求。此时，查询向量在嵌入空间中会严重偏离专业文档的分布空间，导致检索召回大量无关噪声上下文，进而诱发大语言模型（LLM）生成严重的虚假信息与幻觉。

假设文档嵌入（Hypothetical Document Embeddings, HyDE）尝试通过让 LLM 在检索前先生成一份“假设性回答文档”来桥接查询与文档空间的鸿沟。但单路径假设文档具有极高的随机方差：一旦 LLM 在生成假设文档时产生幻觉，整个检索系统将被误导向完全错误的语义方向。

2. 我们的方案：HypoSelectSimRAG

为打破对单一生成路径的脆弱依赖并保证语义锚定，我们提出了 HypoSelectSimRAG 框架。其核心架构由以下三大模块组成：

  • 多路径虚拟文档生成（Multi-Path Generation）： 我们设计了两种提示策略（少样本提示 Few-Shot Prompting 与面向问题分类的提示 Question-Classification Prompting），分别结合双重解码温度（$T=0.1$ 用于保障确定性与精准聚焦，$T=1.1$ 用于激发探索性多样性），构建出 4 条互补的候选假设文档生成路径。
  • 自一致性候选筛选（Candidate Selection）： 我们系统性设计并对比了 5 种文档选择策略：自一致性投票（Self-Consistency Voting）、打分机制（Scoring）、摘要聚合（Summary Aggregation）、平均向量（Average Vector）以及最优相似度向量（Best Vector）。
  • 相似度对齐稠密检索（Similarity-Aligned Dense Retrieval）： 选取与原始查询余弦相似度最高的最优候选文档（Best Vector candidate）投入向量检索器，在本地或分布式向量数据库中完成精准召回。

3. RAGAS 基准评测实验结果

我们在标准评测基准 rag-dataset-1200 上展开全面评估，利用 RAGAS（Retrieval Augmented Generation Assessment）评测套件，从事实准确度（Factual Correctness）、语义相似度（Answer Semantic Similarity）与上下文相关性（Context Relevance）三个核心维度进行打分。

方法 事实准确度 (Factual Correctness) ↑ 语义相似度 (Semantic Similarity) ↑ 上下文相关性 (Context Relevance) ↑
传统标准 RAG (Naive RAG) 0.5257 0.8124 0.5620
HyDE 0.6178 0.8492 0.6350
HypoSelectSimRAG (本文方法) 0.6910 0.8872 0.7180

实验结果表明，HypoSelectSimRAG 相比于传统标准 RAG 在事实准确度上获得了显著的 +31.4% 相对提升，并全方位超越了单路径 HyDE 方法。

4. 工程实现与论文获取

该技术流水线基于 Python 与 LangChain 框架实现，全流程接入 LangSmith 进行 Token 追踪与调用链路监控，并在完整的消融实验集上完成了严格的鲁棒性验证。
